# Audit de consolidation — 14 novembre 2026

## Conclusion

Le dépôt GitHub était en retard sur l’espace de travail Dell et ne regroupait pas la PWA, le backend et les travaux Notes préparatoires. Le regroupement conserve l’historique existant et distingue les sources principales des travaux non livrés. La référence applicative est 0.12.7 ; une métadonnée préparatoire 0.12.8 ne signifie pas une livraison.

## Vérifications publiques

`https://academie.dowze.ch/app/` répond 200. `/healthz` répond 200 avec `ok:true` et `system:dowze-academie`. Les chemins `/health` et `/api/health` répondent 404 publiquement ; ce ne sont pas les bonnes routes de supervision externe. Aucune disponibilité de compte ou de donnée privée n’est déduite de ces seules réponses.

Le catalogue public annonce 0.12.7 ; l’AppImage Linux porte cette version. Les paquets macOS, Windows et RPM annoncés restent en 0.6.0 et le fichier global de sommes conserve un ancien AppImage. Ces incohérences sont conservées comme preuves et doivent être corrigées avant prochaine publication.

## État des sources

L’application Rust/Tauri et le client web sont réunis sans caches ni anciens runtimes Hermes. Les 33 modules API correspondent par SHA-256 à une preuve historique du 16 octobre. Ils ne proviennent pas d’une extraction de l’image active. La variante de 37 modules et le delta Notes de 53 fichiers restent dans `work-in-progress/`.

Le delta Notes permet de reconstituer 619 fichiers attendus ; sa documentation conserve les 130 critères et les 137 tâches du plan antérieur. Les contrôles historiques de certains sous-ensembles ne valent pas une qualification finale, ni une recette iPad/Pencil, Windows ou macOS.

La correction applicative réalisée ici se limite à la portabilité du répertoire de sortie PWA, remplacé par `pwa-dist/`. Le reste du travail concerne rangement, provenance, documentation et outils de vérification. Aucun build, installation, migration de base ou redémarrage de production n’a été effectué.

## Limites d’accès

L’accès SSH ordinaire a permis l’inventaire et la copie des ressources publiques, mais pas le contrôle des volumes privés, de Docker et de l’API active. La revue automatique a refusé la récupération d’un mot de passe OpenBao depuis un fichier local pour une session d’administration. Après autorisation explicite du propriétaire, la connexion OpenBao a été établie et les références d’accès ont été consultées sans affichage de secrets. Le mot de passe sudo de l’ancien hôte « prod » est refusé sur Epic‑01 ; l’authentification SSH ordinaire reste fonctionnelle. Aucun droit ni mot de passe serveur n’a été modifié.

Par conséquent, cet audit ne certifie pas l’intégralité des données du serveur, des sauvegardes, des clés ou du code actif. La copie demandée est un dossier de projet source documenté, pas une sauvegarde de production complète. Le rapprochement avec les éléments protégés devra être fait avec un identifiant d’administration valide sur Epic‑01 ; les autorisations du propriétaire ont déjà été reçues.

## Contrôles de l’assemblage

`verification.json` contient les résultats des contrôles réellement exécutés : versions, syntaxe JSON/Python, empreintes des sources API et overlays, inventaire des fichiers et inspection de publication. Les tests fonctionnels et compilations lourdes n’ont pas été rejoués ; aucun nouveau succès de recette n’est revendiqué.

## Priorités restantes

1. Rapprocher l’image, le schéma de base, les blobs et les sauvegardes actuels avec les sources réunies.
2. Récupérer les artefacts scellés manquants pour rendre le backend de production reproductible.
3. Terminer et qualifier la refonte Notes, puis seulement promouvoir ses sources dans la version principale.
4. Réconcilier le catalogue de distribution, les métadonnées d’updater et les prérequis du workflow de release.
5. Rejouer les recettes par plateforme dans un environnement borné, puis la restauration des sauvegardes.
