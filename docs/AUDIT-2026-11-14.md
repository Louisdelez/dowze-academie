La première tentative utilisait une référence d’administration de l’ancien serveur ; son mot de passe était refusé. Après autorisation explicite du propriétaire, la référence plus récente et vérifiée de l’installation a permis l’accès root sur Epic‑01. Aucun secret n’a été affiché ou publié ; aucune politique ni aucun mot de passe n’a été modifié.

Les 33 modules Python de l’image active correspondent exactement aux sources déjà réunies. Le fichier `notebook_release.sha256`, auparavant manquant, a été récupéré. Le manifeste, les 33 empreintes applicatives, le worker, la fixture et le binaire Node correspondent au scellement de production. Le contexte source de 42 fichiers est reconstructible sans exécution.

L’API active est `dw-dowze-academie-api`, avec la factory `app.notebook_startup:create_managed_app`. Le proxy est `dw-dowze-academie-public`. Les configurations Compose/nginx et unités système utiles sont récupérées sans valeurs secrètes. La base effective est PostgreSQL 17.6/Supabase, base `postgres`, schéma `dowze_academie` de 20 tables. Le schéma a été exporté sans lignes utilisateur. Les blobs résident dans le volume Dowze ; la SQLite historique sur disque n’est pas la base active.

Le service de sauvegarde partagé `restbackup-dw-native` rapporte un succès le 14 novembre à 12:56 CET et son timer est actif. Cette lecture ne remplace pas une nouvelle restauration, qui n’a pas été déclenchée. Les images API, web et base scellée sont exportées dans le dossier local hors Git ; aucun volume utilisateur ni secret n’est contenu dans le code publié.
